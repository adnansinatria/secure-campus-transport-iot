Simulasi Serangan Man-in-the-Middle

Demonstrasi bagaimana penyerang mencoba menyadap data telemetri menggunakan DNS Spoofing dan Rogue TLS Server, serta bagaimana TLS 1.2 dengan validasi sertifikat berhasil menggagalkan serangan tersebut (Fail-Secure).

Langkah 1
🔍 DNS Query
ESP32 mengirim DNS request untuk domain maroonhoney-*.hivemq.cloud. Attacker mencegat dan mengirimkan IP palsu.
Langkah 2
🔌 TCP Connect
ESP32 tersambung ke IP palsu (Rogue Server) di port 8883, mengira itu adalah broker asli.
Langkah 3
📜 Sertifikat Palsu
Rogue Server mengirim sertifikat dengan CN=Fake-HiveMQ. ESP32 memvalidasi terhadap CA root yang dipercaya.
Langkah 4
🛡️ FAIL-SECURE
ESP32 menolak sertifikat palsu! Koneksi TCP di-reset (RST). Data telemetri tidak pernah terkirim ke attacker.

SISTEM AMAN — Serangan MITM Digagalkan!
TLS 1.2 dengan validasi sertifikat CA berhasil mendeteksi sertifikat palsu dari Rogue Server. ESP32 secara otomatis menolak koneksi (Fail-Secure). Data telemetri GPS tetap terlindungi dan tidak bocor ke penyerang.
✅ DENGAN TLS 1.2

Hasil: FAIL-SECURE

  • ✓ Sertifikat palsu terdeteksi dan ditolak
  • ✓ Koneksi TCP langsung di-reset (RST)
  • ✓ Data GPS tidak pernah terkirim ke attacker
  • ✓ Confidentiality & integrity terjaga
❌ TANPA TLS

Hasil: DATA BOCOR

  • ✕ Tidak ada validasi sertifikat
  • ✕ Data terkirim dalam bentuk plaintext
  • ✕ Attacker membaca lokasi real-time kendaraan
  • ✕ Posisi penumpang terekspos sepenuhnya
